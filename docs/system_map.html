1. 全体像：入口 → 台帳 → 自動化 → 見る場所

横の1行が1つの入り口。左から右へ、人が書いた台帳をスクリプトが読み、Addness と GitHub Pages に数字を書く。点線の箱は池田さんのMacでしか動かない部分。

2. 入口ごとの流れと、数字の取り方

① クラウドワークス（月700万）

  • 流れ：案件募集 → 応募者と個別面談（トスアップ面談。担当は池田・藤原・谷村ほか）→ クローザーアポ → プレ → 契約
  • 記録：AGシート「営業(CWトスアップ)」（1件1行）と「契約者」タブ。月が替わるとファイルが新しくなる
  • 9月：着座332 → 見込み内140 → クローザーアポ71 → 契約10件・売上643.5万
  • 数字：Addness 営業/CW 10本（アポ取り・着座・トスアップ・プレ・契約・売上・飛び・成約率・プレ成約率・平均単価）。数え方の正は kpi-dashboard の sales_kpi_export.py
  • 自動化：Pages「売上と歩留まり」はMacが更新。Addnessへは毎朝（10/4は8:55）入っているが、率・平均単価の2本は10/4に未到着

② Threads 案件掲載（目標1000万・いま0）

  • 流れ：27アカウントが毎日2本「案件募集」を投稿 → 応募DM（マーケ担当が返す）→ アンケート → スクリーニング → ご説明用公式LINE → TimeRex で日程 → AGシート「営業(threads)」に記入 → トスアップ面談 → 以後はCWと同じ
  • 投稿づくり：Macのcronが 18:30・19:05・20:05 に annken_draft.py（ジャンル・型・時刻を決めてNotionに予約）。予備としてActionsが 19:30・20:30・21:30 にも走る
  • 投稿：Actionsの post_all.py がNotionの予約を読み、Threads APIで公開（7時・12時・21〜23時台は15分おき）
  • 見張り：Mac側で 20時アラート・夜の二重投稿チェック・完了通知を公式LINEへ（池田さん宛）
  • 9月：アポ取り39 → 着座17（見込み内4）→ 契約0。表示は9/18以降に大きく落ち、10/4夜から新しい型と時間で対策
  • 数字：Pages「案件掲載ダッシュボード」はNotion投稿表から。Addnessには「threads 契約数」1本だけ。マーケ別のアポ→契約はまだ入っていない（子ゴールあり）

③ Threads 属人「いけ」（目標はThreads合計で1000万）

  • 流れ：池田さんがClaude Codeで投稿を作る → Notion「SNS投稿ログ CW裏側」→ Actionsが自動投稿（キーA）→ note記事2本 → 公式LINE「いけ」→ 3分チェック／「相談」→ TimeRex → 面談（池田さん本人）→ 成約
  • いま：フォロワー331、note閲覧累計323、LINE友だち8（届く6）、相談0・面談0・成約0
  • 記録：面談・成約は「【いけ】属人ルート 面談・成約」シートに1人1行。3分チェックはAddnessフォーム（GAS版・LIFF版は未デプロイ）

  • 元データ：kpi_data_A.json（Macが約8分おき）、line/line_A.json（Actions 毎朝8:05）、funnel_A.json（手入力・9/29で停止）

④ Instagram インフルエンサー（目標1000万・いま0）

  • 流れ：担当（池田・松本・谷村）がインフルエンサーにDM → 返信 → 提携面談（AGシート「インフルエンサーDM」タブ）→ 提携決定 → 提携先のフォロワーにアポ → 着座 → 契約（「インフルエンサー営業数値」営業・契約者タブ）

  • 自動化：まだ無い。最後の取り込みは9/30分まで（10/1に手で実行）。10/4朝の期限に届かず、8本とも stale
  • DM稼働量（Pages dm/）は kpi-dashboard の dm_export.py がシートを gviz で読む。月が替わるたびにシートIDを足す必要がある

7. 読み取って分かった課題（理想を決める材料）

  1. Mac依存が大きい。投稿づくりの本番・Threadsの表示回数の同期・Pagesダッシュボードの更新・案件掲載の見張りとLINE通知は、池田さんのMacが起きていないと止まる。9/22の二重投稿も、Macと予備のActionsの重なりが原因だった。
  2. インスタの数字は自動で入っていない。8本すべてが人の手で、10/4朝の期限に届かず stale。月ごとに変わるシートIDも人が足している。
  3. 案件掲載のファネルがAddnessにない。Threadsで入っているのは契約数1本だけ。マーケ別のアポ取り・飛び・着座・見込み外は、AGシートを人が1行ずつ数えている状態（子ゴールは作ってある）。
  4. 同じ数字を2か所で数えている。kpi-dashboard（Pages）とAddnessに、同じ元データから別々に点を作っている。数え方の正はスクリプトだと決めてあるが、ダッシュボードとAGシートで着座の数え方が違う例がある。
  5. KPIツリーが無い。30本が未配置で、売上 → 契約 → 着座 → アポの上下関係がAddness上で見えない。CW・インスタの18本はゴールにも結びついていない。
  6. AGシートの集計式が壊れている。マーケ集計(threads)は5月の式のまま、集計(threads)の契約数は常に0、データタブのスクリプト設定が列と合っていない。
  7. 秘密情報の扱い。LINEグループに書かれたパスワードがDriveの文書に写っている。LINEのトークンはMacの .env、GitHub Secrets、GASのプロパティに分散している。
  8. 手入力で止まっている数字。funnel_A.json（プロフィールアクセス・noteへのクリック）は9/29で停止。note閲覧はCookieが切れると止まる。
  9. ------- が5ブランチに散らばっている。main が無く、どのブランチが正か分からない。毎朝のルーティンは brave-edison を使っている。
  10. AI用のまとまった地図が無かった。仕組みの説明は各ゴール本文・README・PLAYBOOK・スクリプトのdocstringに分散している（この図がその代わりになる）。
